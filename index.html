关键提醒

  1. 建议每隔 10 分钟回原站刷新一次查看，再回到扩展页面重新读取，避免一直拿旧数据操作。
  2. 扩展读取或批量操作时，可以回原站查看，但不要点击操作原站，以免两边互相打断。
  3. 扩展的目标是高效方便，不代表 100% 正确；请回原站检查核对，发现错误请向作者反馈；个人操作过失与扩展开发者无关。
  4. 批量改状态期间不要手动操作原站；需要人工核对时用「查看原站状态」（只读）。

主要功能

  • 读取：快件查询支持「读取当前页 / 近一个月 / 自定义时段」；流程办理支持待办、已办读取（可按前 N 页）。
  • 流程办理：查看待办、已办，勾选后批量通过或退回；已办页可「实际状态回查」。
  • 实际状态回查（仅已办）：逐个到「快件查询」按单号核对真实状态，显示进度 k/n，查到一条回填一条；全部查完统一关闭查询面板。
  • 快件查询及状态调整：按方向、身份、寄件区域、日期、关键词筛选；顶部状态卡片可多选统计；勾选后可批量改物流状态（可随时取消）或改回原状态。
  • 状态修改历史：本地记录每次改动和结果；可「精确查询」（打开物流状态调整单逐单核对）或「快速查询」（按单号到快件查询核对）原站当前状态；可一键复查结果不明的单、按条件筛选和导出。
  • 打印申请单：扩展内自绘，A4 横向版式，不用跳原站、不用二次确认。
  • 导出 Excel：直接导出当前筛选或勾选结果，只有一张「发车清单」：已按 A4 横向预设列宽、行高和页边距，打印时不用再调，排版清晰合理。
  • 界面：页面字号、表格密度、列宽拖动、冻结表头、恢复默认列宽。
  • 楼宇与区域：维护「寄件楼宇 → 校区区域」对照，筛选更准；设置可导出/导入到其他电脑。
  • 校区与视角：良乡 / 中关村窗口切换，状态卡片按校区视角统计。

以上为部分主要功能列举，当然还有一些其他功能可以探索使用。

值班注意事项

  1. 严格遵守助管值班规范，值班期间不允许带私人电脑、打游戏、看视频及做其他与工作无关的事情。
  2. 早上值班同学仔细核对快件数目（揽件和派件）；有之前因老师不在办公室等原因未及时派送的老师快件，要尽快送一下。
  3. 发车前仔细核对当天快件数目，不要出现贴错单子、或者把空信封及空袋子寄到中关村的工作失误。
  4. 晚班同学下班前核对好快件数目（揽件和派件），打卡下班。
  5. 取件时间：上午取件截止到 11:30，下午取件截止到 16:30；超过时间的快件要及时和老师沟通好（下一个时间点取，或者麻烦老师助管送）。
  6. 成绩单及在学证明：每周一、周四上午 10:30，在图书馆侧边的档案馆取申请的在读证明及成绩单。取到的文件分为良乡件和中关村件：良乡件交综合窗口，中关村件由值班同学下单，走当天班车送至中关村学生服务大厅。
  7. 寄件内容为 50 页以内的纸质文件，不接收发票、身份证、银行卡等贵重物品，收件同学一定要注意！
  8. 图书馆、户籍卡、成绩单等件一定要下单才能发出。

改状态之前，先确认这几件事

  1. 原站标签先备好：确保「【流程】」「快件查询」「京工飞鸿两校快件系统」三个标签都在，并试开一次「物流状态调整单」，确认不卡、不报错，再回工作台批量操作。
  2. 待办不能直接改：待办里的单先在「流程办理」勾选 →「批量通过」，变成已办后才能改物流状态。
  3. 先核对再提交：批量前逐个核对单号、寄件人、收件人；重复单号会被禁止修改。
  4. 网络慢先读一次：原站页面没加载完就读，可能读到空列表；先点「读取当前页」确认数据是最新的。
  5. 批量时别手动操作原站：扩展和你在抢同一张调整单，容易互相打断。要人工核对，用「查看原站状态」（只读）。
  6. 定时回原站查看：不要一直只看扩展页面。建议每隔 10 分钟，在当前批量操作结束或暂停后，回原站刷新并查看，再回扩展重新读取原站列表。批量执行期间不要刷新或操作原站。
  7. 提交后要确认两件事：只有看到「提交成功」并且调整单标签自动关闭，才算改好；少一个就记为「结果不明」，先按单号核对，别连续重复提交。
  8. 随时可以取消：批量改状态过程中，弹窗里的「取消」一直可用。提交前取消＝本单不提交；已经发出提交再取消＝停止等待、剩余单不再执行，这一单结果要到原站核对。

常见问题

为什么显示“结果不明”？
没同时看到“提交成功”和调整单自动关闭。先到原站按单号查一次：没改再重试，不要连续重复提交；确认改成功了就在历史里标一下即可。
为什么卡在“等待原站点确定”？
门户的确认弹窗没响应。扩展最多等 90 秒，报“提交结果待核验”。这时到原站手动点一次「确定」完成本次提交，再回历史里点「查看原站状态」核对。
提交时弹出“控件【…】数据不完整”怎么办？
这是原站对个别单子的校验提示，提示内容中可能出现 @#@ 等特殊字符。扩展会自动点「确定」，等这个提示框关掉后再点一次「提交」；如果重新提交后仍被拦，会记成失败并在历史里写明原因（这种是原站数据一直不全，需要按提示补全地址后手动处理）。
待办里的单为什么改不了状态？
原站限制：待办只是“待审”，必须先通过进入已办，才会生成可调整的寄件单。
读“已办”后状态全是“订单申请”？
原站把已办的状态一律写成“订单申请”。在工作台「流程办理」→「已办」里点「实际状态回查」，会逐单到「快件查询」核对真实状态；读取已办本身不再自动回查，以免读 100 单等几分钟。
“自定义时段 / 近一个月”读完之后，原站查询面板要手动关吗？
不用。批量读取结束后扩展会自动先点条件行红色错号、再点「关闭查询」，回到快件列表。
批量改状态中途停了 / 连续失败怎么办？
如果是原站一直“加载中”，扩展会把当前单记失败并停止整批，提示你到原站刷新页面；如果只是个别单失败，会继续下一单，原因都写在「状态修改历史」里。
怎么取消批量改状态？取消后已经提交的单怎么办？
改状态弹窗里的「取消」随时可点。取消前已经发出提交的单无法撤回，扩展会停止等待并记“结果不明”，这些单请用「查看原站状态」核对；未开始的单不会再执行。
打印的信息单和原站不一样？
字段一致，版式是扩展内自绘（A4 横向）。原站打印要跳标签、二次确认，扩展省掉了这两步。
换电脑后楼宇映射和历史没了？
数据存在本机浏览器里。旧电脑「楼宇与区域 → 导出设置」，新电脑「导入设置」；历史记录不随设置导出。
提示“后台版本不匹配”？
扩展更新后没重新加载：到 edge://extensions 点扩展卡片上的刷新，再回门户点图标。只刷新工作台页面不会更新后台。

开发者心声

做京工飞鸿这个扩展的初衷其实很简单，就是想让大家在窗口值班时少做一些重复的操作，少一些繁琐的点击，让日常工作能更方便高效一些。

目前由于没有学校的数据接口，也没有学校服务器端的开发权限和相关技术资料，因此无法直接开发新网站或对原有系统进行改造。经过不断尝试，并兼顾考虑安全性、稳定性和有效性，最终选择了浏览器扩展的方式：通过识别、映射原网站页面，在原网站现有功能的基础上进行辅助操作和功能扩展，不直接访问学校后台数据库。扩展使用时仍会通过原网站读取和提交数据。

开发这个工具并不轻松：从最初的想法到现在，前后迭代了成百上千个版本，很多功能都是反复改代码、反复测试、再回到原站一步一步核对出来的，中间也走过弯路、出过问题。最后才慢慢打磨出现在这个相对稳定、高效、功能比较完整的版本，并无偿提供给大家使用；源码也已在本项目的 GitHub 仓库半开源（可查看、可下载，但禁止修改与衍生分发），欢迎查看、指正和一起维护。

这个项目从最初的想法到现在，都是在实际使用中一点点摸索、开发和完善的。如果使用过程中遇到问题，或者有更好的想法和建议，欢迎联系作者一起交流，无论是功能建议、使用体验，还是代码层面的改进，都非常欢迎。反馈问题时，请附上清晰的截图、错误提示和个人想法。作者也会根据大家的使用情况和反馈，持续维护和更新，尽可能让它越来越好用。

如果你也对这个项目感兴趣，愿意参与开发，欢迎和作者沟通，后续也可以邀请你加入项目成为协作者，一起维护和完善京工飞鸿扩展。

如果觉得这个工具还不错，不妨到 GitHub 上帮作者点亮一颗免费的 Star ⭐，这是对一个独立开发者很好的鼓励。也欢迎关注项目仓库，留意后续更新，并下载最新版本使用。
