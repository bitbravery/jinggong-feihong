# v0.9.167 改动说明（第 0 级：只加诊断）

基于 v0.9.163。**不改变任何点击、等待和读取判断**，只把流程读取的过程显示出来，用于找出"读已办卡住"的原因。

## 改了什么
1. **进度条显示当前步骤**：流程页「读取当前页」「读取前 N 页」时，进度条末尾实时显示扩展正在做什么、已用几秒，例如：
   - `检查流程列表：doneList.htm 列表加载中（已 2.3 秒）`
   - `切到「已办」：点了「已办」，等待切换；识别到 doneList.htm:待办（已 3.1 秒）`
   - `原站列表：doneList.htm 20 行/共 27254 条/第 1 页；未就绪：…（已 9.8 秒）`
2. **「诊断」新增两块**：
   - **流程页现状**：每个流程列表页的路径、是否可见、识别出的当前分类（待办/已办）、加载遮罩个数、完整表头、各种取行方式取到的行数、分页文字。
   - **最近一次流程读取的步骤**：按时间列出每一步，重复的步骤合并计数。
3. 注入层在"等待"时附带原因（如"表头里没有'单号'""列表加载中"），只用于显示。

## 怎么确认没改行为
用 v0.9.163 原版与本版的编排层跑同样的 5 个流程场景（已在分类、需切换且列表慢、前 N 页切换慢、一直识别不出、下一页），对门户发出的每一条命令、每一次等待时长和最终结果逐条比对，完全一致。

## 检查
- 新增 `流程诊断检查.cjs`；其余 52 个检查未改动，全部通过（共 53 个）。

## 请这样帮忙取证
1. 在 `edge://extensions` 重新加载扩展，回学校页面点一次飞鸿图标。
2. 复现一次"读已办卡住"：卡住时截一张工作台（看进度条上的步骤），再截一张门户。
3. 不用等它结束，直接点「诊断」→「复制」，把内容发过来。
