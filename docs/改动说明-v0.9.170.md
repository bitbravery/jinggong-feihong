# v0.9.170 改动说明（第 2 级：写入安全 + 每单分段计时）

基于 v0.9.169。只动写入（改状态、改回、查看状态）相关的部分；**流程读取一行未改**（与 v0.9.169 对照 5 个流程场景，发给门户的命令与等待完全一致）。
内容取自之前保存的 0.9.164/0.9.165 改动中写入相关的部分，读取相关部分一律未带回。

## 改了什么
1. **「改回原状态」先核对再提交**
   - 先等表单联动出联系人（不联动就按 点空白→回车 补触发，共 3 次）；新表单"当前状态"默认勾第一项，以前可能把默认值当成真实状态。
   - 原站现状必须仍是"上次改成的状态"才改回；若已被别人改成别的状态，停下并说明，不覆盖。
   - 提交那一刻再核对一次（注入层 `submitBare`：联系人已联动、现状符合预期）。
2. **原站操作排队，一次只做一件事**
   - 编排层：所有操作原站的请求排队执行；准备好一单到提交完成之间，**其他工作台**的操作要等（同一工作台不受影响；持有准备的工作台关掉后自动放行）。取消、诊断、消息提醒不排队。
   - 工作台：批量查看状态遇到改状态/改回/读取进行中会等待；批量查看进行中不能开始改状态或改回（会提示）。
3. **姓名核对：只记录，不拦截**
   - 联动出的寄件人、收件人与工作台记录都对不上时（去空白与 `@#@` 后比较），写进该单历史与「复制修改信息」的「姓名核对」列；照常提交。
4. **每单分段用时**
   - 「复制修改信息」新增「分段耗时(秒)」列，例如：`准备[门户0.3 表单4.1 联动(第1次)6.0] 提交[点提交0.4 确认2.1 收尾5.3]`。
   - **「联动(第 N 次)」表示第几次触发联动才出订单信息**——用来确认录屏里"填了单号不联动"的问题现在还在不在。
   - 历史详情里也会显示用时。

## 检查
- 新增 `原站串行检查.cjs`、`姓名核对记录检查.cjs`；更新 `改回原状态检查.cjs`（契约变化：改回必须带"上次目标状态"，并须等联动）。
- 共 57 个检查全部通过；分别撤掉排队锁、改回联动等待、改回现状核对后，对应检查均会失败。

## 请这样验证（建议 3～5 单小批量）
1. 重新加载扩展，回学校页面点一次飞鸿图标。
2. 选 3～5 单批量改状态；结束后点「复制修改信息」，把内容发给维护者（重点看「分段耗时」里联动是第几次出来的）。
3. 在「状态修改历史」对刚改的一单点「改回原状态」：应先等联动、再提交。
4. 点「批量查看状态」后马上去改状态：应提示等待。
