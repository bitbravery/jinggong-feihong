## 三、架构

| 文件 | 职责 |
| --- | --- |
| `manifest.json` | MV3，权限仅 `activeTab,scripting,storage`，**不申请 host_permissions**，无任何 fetch/XHR |
| `worker.js` | Service Worker：收工作台消息，用 `chrome.scripting.executeScript(allFrames, world:'MAIN')` 注入 `sourceAction` 驱动门户 |
| `source.js` | 注入到门户执行的命令集合（查询/翻页/提交/确认/读表单/流程分类/打印…） |
| `live.js` | 工作台 UI 逻辑：读取循环、提交、历史、导出、打印模板、设置 |
| `bulk.js` | 批量读取：快件分页 `scanAll`、流程分页 `scanFlows` |
| `export.js` | 手写 OOXML 生成 xlsx（两张表：发车清单 16 列 / 完整数据 20 列） |
| `date-range.js` | 日期范围校验与格式化 |
| `mapping.js` / `logic.js` / `row-layout.js` / `table-layout.js` / `sidebar-layout.js` / `perspective.js` / `audit-history.js` / `write-policy.js` | 字段映射、状态判定、表格布局、历史、写权限 |

## 四、关键设计决定（不要轻易推翻）

1. **不申请站点权限**：只靠 `activeTab` + `scripting` 注入当前标签页。因此**无法操作另一个标签页**（例如原站新开的打印页）。
2. **提交后不回读**：点完确认即视为完成，历史里记「已确认提交（未回读）」。用户明确要求省时间。
3. **打印走自绘**：`打印申请单` 不再操作原站，用已读数据在扩展内渲染「寄件申请信息单」（A4 横向、隐藏 iframe 打印）。
4. **待办单不可改物流状态**：必须先原站「批量处理 → 通过」变已办，才会进入良乡申请寄件；扩展对此做了禁用与拦截提示。
5. **导出命名**：`飞鸿清单YYYYMMDD.xlsx`，同日重复导出加 `(1)(2)`（计数存 localStorage，按天）。
6. **序号**：默认 1..N，点表头切「原站序号」再点切回。

## 五、流程页（最容易踩坑的地方）

门户「流程」页有两个列表帧同时存在：`haveToDoList.htm`（待办）与 `toDoList.htm`（已办），切换分类只是显隐。

- 判断“当前分类”用**标签样式差异**（颜色/字重/下边框），不靠路径；
- 读取只认**网格可见**的帧（行元素 `offsetHeight>0`）；
- 翻页只在可见帧点「下一页」；第 1 页若「下一页」不可点就直接结束（单页列表）；
- 读取完成后**把原站分页复位到第 1 页**；
- 读取结果**按分类合并**（`setSnapshot` 里 `o.flow!==s.flowTab` 过滤后拼接），否则读已办会把待办冲掉。

## 七、数据与隐私

- 数据存浏览器：`localStorage`（`feihong-connector-settings-v1`、`feihong-mappings-v1`、`feihong-office-keywords`）+ `chrome.storage.local`（历史 `feihongAuditV2`）；
- 历史/导出含寄件人、收件人姓名与电话（仅本机，不外传）；
- 诊断面板只输出帧路径与结构，不含姓名电话。

## 八、已知限制

1. 打开发送单打印页是**另一个标签**，扩展无法注入（无站点权限），所以最后的「打印」由用户点；
2. 流程分类自动切换依赖标签样式差异，若门户改版需同步调整 `flowActiveTab`；
3. 批量通过/退回是写操作，首次使用请先用 1 单验证。
