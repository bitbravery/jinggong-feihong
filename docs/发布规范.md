# 发布规范（v1.0.13 起）

目标：**任何人都能从仓库首页一步拿到可用的安装包**，并且每个版本都能读清楚改了什么、有什么坑。

---

## 一、版本号

- 格式 `x.y.z`（当前 1.0.13），每次功能或修复 +1，不复用；
- 四个文件必须同步，`tests/版本一致性检查.cjs` 会校验：

| 文件 | 位置 |
| --- | --- |
| `manifest.json` | `"version": "x.y.z"` |
| `worker.js` | `const COMPONENT_VERSION = 'x.y.z';` |
| `live.js` | `if(c.version!=='x.y.z')` |
| `index.html` | 侧栏 `接入版 vx.y.z · 提交核验版` |

## 二、发布前检查清单

1. `Get-ChildItem tests -Filter *.cjs | ForEach-Object { & node $_.FullName }` —— 全绿（当前 85 项）；
2. 真机自检六项：版本号、读取、流程读取、打印预览、导出能打开、批量改状态能取消；
3. 若改了写入逻辑：用测试单跑一次「订单申请 → 已揽件」并核对原站；
4. 扫描是否有真实姓名 / 手机号 / 单号进入仓库（示例数据用 `13800000000` 之类占位）；
5. 打包（排除 `.git` 与 `_*` 临时脚本），记录 SHA256。

## 三、打包

```powershell
$root='D:\Desktop\京工飞鸿\接入版'
$zip="D:\Desktop\京工飞鸿\jinggong-feihong-vx.y.z.zip"
if(Test-Path $zip){Remove-Item $zip -Force}
Add-Type -AssemblyName System.IO.Compression.FileSystem
$z=[System.IO.Compression.ZipFile]::Open($zip,'Create')
Get-ChildItem $root -Recurse -File |
  Where-Object { $_.FullName -notmatch '\\\.git\\' -and $_.Name -notlike '_*' } |
  ForEach-Object {
    $rel=$_.FullName.Substring($root.Length+1).Replace('\','/')
    [System.IO.Compression.ZipFileExtensions]::CreateEntryFromFile(
      $z,$_.FullName,$rel,[System.IO.Compression.CompressionLevel]::Optimal) | Out-Null
  }
$z.Dispose()
Get-FileHash -LiteralPath $zip -Algorithm SHA256
```

- 压缩包内**根目录**必须是 `manifest.json`（不要再套一层文件夹）；
- 条目数约 130；文件名用英文（`jinggong-feihong-vx.y.z.zip`），中文名在 Release 上传时会被转义成乱码。

## 四、发布 Release

1. 推代码：`git add -A && git commit -m "…" && git push`；
2. 打 tag 并推送：`git tag vx.y.z && git push origin vx.y.z`；
3. 打开仓库右侧 **Releases → Draft a new release**，选择该 tag；
4. 标题：`京工飞鸿 提交版 vx.y.z`；上传上面的 zip；
5. 说明正文固定三段：

```markdown
## 本次修复
- …

## 已知问题
- …

## 兼容性与校验
- Edge 120+（Chromium MV3）；85 项本地检查通过
- SHA256: `…`
```

6. 发布后回读页面，确认附件可下载、SHA256 与本地一致。

## 五、README 顶部入口

README 第一屏固定放「下载」块，指向 `releases/latest` 与具体版本的 zip 直链，修改时同步更新版本号与 SHA256。

## 六、不要做的事

- 不要把 zip、xlsx、日志提交进仓库（`.gitignore` 已排除）；
- 不要推旧 tag（历史里可能含早期样例数据）；
- 不要在说明里承诺“全自动”“绝对不出错”这类无法验证的话。
