# v0.9.180 改动说明：写入加固（风险清单第 2、5 条）

基于 v0.9.179。

## 1. 问题（代码确认）
- **第 2 条**：提交后"调整单标签消失"会被当成提交成功。若标签是门户因错误关闭、或被手动关闭（并没有点过「确定」），也会记成"已改好"。
- **第 5 条**：批量通过/退回点「确定」时，点的是页面上**第一个**看得见的含「确定」的弹窗/面板，可能点到别的弹窗；点完只返回"已点"，不核对原站是否真的处理。
- 风险清单第 4 条（回查后自动重试会重复提交）复核后**不成立**：重试会重新打开调整单联动、核对"原站当前状态 = 工作台原状态"，若第一次其实已生效会在这里停下，不会再提交。本版不改。

## 2. 改动
- `source.js`
  - `submissionComplete`：带本单令牌时，标签消失还必须"本单点过「确定」"（confirmSubmit 记在门户顶层的 `__fhPressed`）才算完成；否则返回 `tabGoneNoPress`，继续等待，最终走"结果不明"按单号回查。
  - 新增 `dialogMark`：把此刻看得见的弹窗/面板标为旧的；`flowDialogOk` 只点**之后新出现**的弹窗里的「确定」。
- `worker.js`：批量提交、改回的"标签消失"信号带上本单令牌；批量通过/退回在点「通过/退回」菜单前先 `dialogMark`。
- `live.js`：批量通过/退回结束后自动读取待办当前页，核对所选单号是否还在「待办」；还在就提示到原站核对。

## 3. 待确认
- 现场做一次批量通过：结束后应看到"已核对：所选 N 单已不在原站「待办」当前页"。
- 若门户的批量通过确认弹窗其实是点菜单前就已存在的同一个元素（被重用且一直可见），`flowDialogOk` 会等 8 秒后报"未见确认弹窗"——届时请把提示与「诊断」发回。

## 4. 检查
- 新增 `写入加固检查.cjs`：没点确定标签就没了→不算；点过本单确定→算；点的是别的提交→不算；只点新弹窗的确定；点菜单前先标记；结束后核对待办。用 v0.9.179 代码跑会失败。
- 共 62 个检查全部通过。

## 5. 回退
