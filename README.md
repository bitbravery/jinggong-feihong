# 京工飞鸿 · 两校区快件工作台

北京理工大学良乡、中关村两个快件窗口用的浏览器扩展。它在学校门户（ehall）上替值班同学做那些重复的点击：读取快件和流程列表、按状态和校区分类、批量改物流状态、批量通过待办、打印寄件申请信息单、导出发车清单。

## 下载

最新版本：[v1.0.20](https://github.com/bitbravery/jinggong-feihong/releases/tag/v1.0.20)，安装包 [`jinggong-feihong-v1.0.20.zip`](https://github.com/bitbravery/jinggong-feihong/releases/download/v1.0.20/jinggong-feihong-v1.0.20.zip)。SHA256 写在发布页的说明里，下载后可以用 `certutil -hashfile 文件名 SHA256` 对一下。

所有版本在仓库右侧的「发布」（Releases）里。只想看源码可以用 `Code → Download ZIP`，但那不是打好的安装包，版本号要自己确认。

## 安装

Edge、360 浏览器、Chrome 这类能装扩展的 Chromium 内核浏览器都可以，下面以 Edge 为例。

1. 下载上面的 zip，解压到一个固定目录，比如 `D:\京工飞鸿\`。以后升级就覆盖这个目录，路径别变。
   - 解压后这个目录里应该直接能看到 `manifest.json`。如果多套了一层文件夹，加载时选里面那层。
2. 地址栏输入 `edge://extensions`（Chrome 是 `chrome://extensions`），打开「开发人员模式」，点「加载解压缩的扩展」，选这个目录。
3. 打开门户 `https://ehall.bit.edu.cn`，进入「京工飞鸿两校快件系统」，点工具栏上的红色飞鸿图标，会打开工作台。
4. 工作台左下角显示 `接入版 v1.0.20 · 提交核验版` 就装好了。

升级：解压覆盖原目录，在扩展管理页点这个扩展卡片上的刷新按钮，再回门户点一次飞鸿图标。只刷新工作台页面不会加载新的后台代码。

换电脑：旧电脑在「楼宇与区域」里点「导出设置」，新电脑「导入设置」。

带截图的步骤见 [`docs/使用教程.pdf`](docs/使用教程.pdf)，逐项打勾的版本见 [`docs/部署清单.md`](docs/部署清单.md)。

## 日常怎么用

- 门户里保持四个标签：工作台、【流程】、快件查询、京工飞鸿两校快件系统。乱了可以点工作台上的「打开原站标准页面」，扩展会帮你整理好。
- **读快件**：「读取当前页」只读原站正在显示的那一页；「近一个月」「自定义时段」会把这个时间段里所有状态、所有页面都读下来，读完还会回到第 1 页核对一遍有没有变。每次读取都在已有数据上追加，不会把之前读的清掉。
- **流程**：在「流程办理」里选待办或已办，「读取前 N 页」。待办的单要先在原站「批量处理 → 通过」变成已办，才能改物流状态；工作台里也能勾选后一键批量通过或退回。
- **已办的真实状态**：原站已办列表里的物流状态一律显示“订单申请”，不是真的。要看真实状态，在已办里点「实际状态回查」，扩展会逐单去快件查询里查。
- **改物流状态**：勾选后点「批量改状态」，扩展一单一单地在原站调整单里填写、提交。每单提交前都会核对完整单号和原站当前状态，对不上就跳过这一单、记进历史，接着做下一单。只有原站弹出“提交成功”并且调整单自动关闭，才记为成功；少一样就记“结果不明”，不会自动重提。
- **状态修改历史**：保留最近一个月的记录。可以按日期、单号筛选，查看原站现在的状态（快速：走快件查询；精确：打开调整单逐单看），对改错的单一键改回原状态。
- **打印和导出**：「打印申请单」在扩展里直接排版寄件申请信息单，不跳原站；「导出 Excel」生成 `飞鸿清单YYYYMMDD.xlsx`，同一天多次导出会自动加 `(1)` `(2)`。

扩展在批量读取或改状态时，可以切回原站看，但别在原站上点操作，两边会互相干扰。改状态前后各刷新一次原站，原站不容易卡。

## 权限和数据

- 只申请 `activeTab`、`scripting`、`storage` 三个权限，不申请任何网站权限，也不发任何网络请求（扩展页的 CSP 是 `connect-src 'none'`）。
- 所有操作都是注入到你自己打开的门户页面里执行的，相当于你本人在点。门户要求登录的地方，扩展用的就是你的登录状态。
- 读到的数据和历史记录只存在本机浏览器里，不上传。

## 已知限制

1. 打印的申请单是扩展按门户表单的字段自己排的，不是门户的原页面。
2. 流程页的分类切换依赖门户现在的页面结构，门户改版后可能要跟着改。
3. 批量通过、退回、改状态都会真的改原站数据，第一次用请先拿一单试。
4. 提交后不回读原站。想确认的话，在历史里用「查看原站状态」查。
5. 待办超过一页时，本地的待办列表只会增加不会减少（没法确认其余页里有没有），批量通过后的核对也只看当前页。

## 开发

```powershell
# 在仓库根目录运行全部检查
Get-ChildItem tests -Filter *.cjs | ForEach-Object { & node $_.FullName; if ($LASTEXITCODE -ne 0) { "FAIL: $($_.Name)" } }
```

`tests/` 里每个 `.cjs` 都是一项独立检查，直接用 Node 跑，没有依赖。改完要全部通过。版本号在 `manifest.json`、`worker.js`、`live.js`、`index.html` 四处，必须一致，`tests/版本一致性检查.cjs` 会查。

```
manifest.json          扩展清单
worker.js              后台：排队、注入、等待、判定结果
source.js              注入到门户页面里执行的各条命令
live.js                工作台界面
index.html / style.css 界面和样式
export.js、bulk.js、mapping.js 等  各自一块功能
tests/                 本地检查
docs/                  教程、部署清单、交接文档
```

版本记录见 [`CHANGELOG.md`](CHANGELOG.md)，发布步骤见 [`docs/发布规范.md`](docs/发布规范.md)，设计上的取舍和踩过的坑见 [`docs/交接文档.md`](docs/交接文档.md)。

## 加载时报 “Cannot load extension with file or directory name _xxx”

扩展目录里不能有以 `_` 开头的文件或文件夹，浏览器会拒绝加载。用发布页的 zip 解压到一个干净的目录再加载就不会有这个问题；如果已经出现，删掉那个 `_` 开头的文件，再点「重试」。
