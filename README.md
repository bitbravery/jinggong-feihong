# 京工飞鸿 · 两校区快件工作台

北京理工大学良乡、中关村两个快件窗口用的浏览器扩展。它在学校门户（ehall）上替值班同学做那些重复的点击：读取快件和待办、按状态和校区分类、审批待办、批量改物流状态、打印寄件申请信息单、导出发车清单和取送件清单，还能一键把原站整理成标准的四个标签。

## 安装

Edge、360 浏览器、Chrome 这类能装扩展的 Chromium 内核浏览器都可以，下面以 Edge 为例。

1. 下载上面的 zip，解压到一个固定目录，比如 `D:\京工飞鸿\`。以后升级就覆盖这个目录，路径别变。
   - 解压后这个目录里应该直接能看到 `manifest.json`。如果多套了一层文件夹，加载时选里面那层。
2. 地址栏输入 `edge://extensions`（Chrome 是 `chrome://extensions`），打开「开发人员模式」，点「加载解压缩的扩展」，选这个目录。
3. 打开门户 `https://ehall.bit.edu.cn`，进入「京工飞鸿两校快件系统」，点工具栏上的红色飞鸿图标，会打开工作台。
4. 工作台左下角显示 `接入版 v1.0.34 · 提交核验版` 就装好了。

升级：解压覆盖原目录，在扩展管理页点这个扩展卡片上的刷新按钮，再回门户点一次飞鸿图标。只刷新工作台页面不会加载新的后台代码。

换电脑：旧电脑在「楼宇与区域」里点「导出设置」，新电脑「导入设置」。

带截图的完整说明见 [`docs/技术说明与使用指南.pdf`](docs/技术说明与使用指南.pdf)（安装、日常操作、打印与导出的新旧对比、常见问题），逐项打勾的版本见 [`docs/部署清单.md`](docs/部署清单.md)。

## 日常怎么用

- **整理原站标签**：门户里保持四个标签：工作台、【流程】、快件查询、京工飞鸿两校快件系统。乱了就点侧栏的「打开原站标准页面」：先关掉多余和重复的标签，再按 快件查询 →【流程】→ 京工飞鸿两校快件系统 的顺序只打开还缺的，已经是这四个时什么都不动，最后切到快件查询。失败时提示会写明卡在第几步，截图发给作者就能定位。
- **读快件**：「读取当前页」只读原站正在显示的那一页；「近一个月」「自定义时段」（默认近一周，可改起止日期）会把这个时间段里所有状态、所有页面都读下来，读完还会回到第 1 页核对一遍有没有变。每次读取都用这次读到的结果刷新列表，原站上变了的状态、已经不在的单会跟着更新。
- **读完自动做的两件事**：「近一个月 / 自定义时段」读完快件查询后，会接着读原站全部待办；再给本校区发出、只有日期的单到原站「已办」补上下单时分。已经有时分的跳过，找过没找到的记在本机、以后不再重复找；另一校区发出的单不在本窗口的已办里，不去找。
- **待办审批**：分类标签最前面是「待办 N」，列出本窗口校区发出、等审批的新单，有待办时标签变蓝。每行有「通过 / 退回 / 打印申请单」，也能勾选后批量通过或退回；处理完扩展会重读全部待办，核对这些单是否已经离开待办。通过的单下次读取后出现在快件查询里，那时才能改物流状态。
- **勾选**：切换分类标签、改筛选条件时，已勾选的单会保留，选择栏会提示其中几件在其他标签里。待办和普通单不能混在一起操作，混着勾时按钮会变灰。
- **改物流状态**：勾选后点「批量改状态」，扩展一单一单地在原站调整单里填写、提交。每单提交前都会核对完整单号和原站当前状态，对不上就跳过这一单、记进历史，接着做下一单。原站以“数据不完整”拒收的单（多是地址里的楼宇原站已经不认了），要先在原站把地址改好。只有原站弹出“提交成功”并且调整单自动关闭，才记为成功；少一样就记“结果不明”，不会自动重提。
- **状态修改历史**：保留最近一个月的记录。可以按日期、单号筛选，查看原站现在的状态（快速：走快件查询；精确：打开调整单逐单看），对改错的单一键改回原状态。
- **打印和导出**：「打印申请单」在扩展里直接排版寄件申请信息单，不跳原站；「导出 Excel」生成 `飞鸿清单YYYYMMDD.xlsx`，同一天多次导出会自动加 `(1)` `(2)`。
- **导出取送件**：勾选单子后点「批量改状态」右边的「导出取送件」，生成 `取送件清单YYYYMMDD.xlsx`，发给去老师那里取件、送件的同学。可选两种排法：「取送件优先」上面全是送件、下面全是取件，中间隔开；「楼宇优先」按区域 → 楼宇 → 房间混排，同一栋楼的取送挨在一起。送件蓝色、取件橙色，学生的单照样导出并标「学生」。A4 横向，打印不用再调。

批量读取、改状态这类长操作期间，扩展会把原站页面切到前面，做完再切回工作台：浏览器会给后台标签页限速，原站放在后台容易超时失败。期间请别切走，也别在原站上点操作；进度看工具栏飞鸿图标上的数字。改状态前后各刷新一次原站，原站不容易卡。

## 权限和数据

- 只申请 `activeTab`、`scripting`、`storage` 三个权限，不申请任何网站权限，也不发任何网络请求（扩展页的 CSP 是 `connect-src 'none'`）。
- 所有操作都是注入到你自己打开的门户页面里执行的，相当于你本人在点。门户要求登录的地方，扩展用的就是你的登录状态。
- 读到的数据和历史记录只存在本机浏览器里，不上传。

## 已知限制

1. 打印的申请单是扩展按门户表单的字段自己排的，不是门户的原页面。
2. 读待办、补下单时分、「打开原站标准页面」都依赖门户现在的页面结构，门户改版后可能要跟着改。
3. 批量通过、退回、改状态都会真的改原站数据，第一次用请先拿一单试。
4. 提交后不回读原站。想确认的话，在历史里用「查看原站状态」查。
5. 另一校区发出的单补不上下单时分（它们不在本窗口的已办里），只显示日期。

## 开发

```powershell
# 在仓库根目录运行全部检查
Get-ChildItem tests -Filter *.cjs | ForEach-Object { & node $_.FullName; if ($LASTEXITCODE -ne 0) { "FAIL: $($_.Name)" } }
```

`tests/` 里每个 `.cjs` 都是一项独立检查，直接用 Node 跑，没有依赖。改完要全部通过。版本号在 `manifest.json`、`worker.js`、`live.js`、`index.html` 四处，必须一致，`tests/版本一致性检查.cjs` 会查。

```
manifest.json          扩展清单
worker.js              后台：排队、注入、等待、判定结果
source.js              注入到门户页面里执行的各条命令
live.js                工作台界面
index.html / style.css 界面和样式
export.js、bulk.js、mapping.js 等  各自一块功能
tests/                 本地检查
docs/                  教程、部署清单、交接文档
```

版本记录见 [`CHANGELOG.md`](CHANGELOG.md)，发布步骤见 [`docs/发布规范.md`](docs/发布规范.md)，设计上的取舍和踩过的坑见 [`docs/交接文档.md`](docs/交接文档.md)。

## 加载时报 “Cannot load extension with file or directory name _xxx”

扩展目录里不能有以 `_` 开头的文件或文件夹，浏览器会拒绝加载。用发布页的 zip 解压到一个干净的目录再加载就不会有这个问题；如果已经出现，删掉那个 `_` 开头的文件，再点「重试」。
